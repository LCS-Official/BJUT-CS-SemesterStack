# 实验设计方案：老师给定楼梯转角单题场景

本阶段目标不是继续扩展八个自定义场景，而是先围绕老师提供的一个楼梯转角题目跑通完整流程：构造 Prompt、调用多模态模型、采集回答、自动预标注、人工复核、统计分析。

## 1. 场景定义

题目场景为真实楼梯转角。模型输入包含：

- 一张真实照片：`楼梯转角实地图.jpg`。
- 文字给出的全部尺寸信息。

注意：`题目示意图.png` 只用于我们整理题面和基准答案，不能发送给模型。采集脚本已加入保护，如果 `image_path` 指向 `题目示意图.png` 会拒绝发送。

## 2. 已知尺寸

- 轮椅占地近似为矩形。
- 轮椅前后长：`121cm`。
- 轮椅左右宽：`68.5cm`。
- 左侧主平台竖向净长：约 `140cm`。
- 左下入口净宽：约 `110cm`。
- 右下出口净宽：约 `110cm`。
- 右侧竖向区域净宽：约 `70cm`。
- 右上井道宽：约 `70cm`，不可通过。
- 中右部斜向边界长度：约 `106cm`。
- 斜边两端附近各有约 `15cm` 的短边。

## 3. 新增运动约束

轮椅只能沿当前朝向直线前进或后退。需要转弯时，必须先停下来再调转方向；不能在移动过程中连续画弧转弯。

这意味着模型不能只按“转弯半径”粗略判断，还需要考虑是否存在由若干段直线移动和停车调向组成的无碰撞路径。

## 4. 数据集结构

当前 `data/prompt_matrix_seed.csv` 包含 12 条 Prompt，全部对应同一场景 `T1`，并全部发送 `楼梯转角实地图.jpg`。

Prompt 层级应严格区分信息形式：

- `L1`：自然语言和照片理解层。不给厘米级尺寸数字，只描述“真实楼梯转角、右上井道不可通过、轮椅只能直线移动并停车调向”等核心事实。
- `L2`：完整参数层。给出轮椅尺寸、入口/出口宽度、平台尺寸、井道宽度、斜边长度、短边长度等全部尺寸。
- `L3`：形式化建模层。将问题表述为二维矩形刚体、配置空间、碰撞检测或有限段直线平移加停车调向的路径存在性问题。

扰动类型：

- `none`：基线表述。
- `motion_constraint_emphasis`：强调直线运动和停车调向。
- `visual_crosscheck`：要求照片结构与文字尺寸交叉核对。
- `irrelevant_visual_detail`：加入照片外观干扰。
- `path_region_hint`：给出候选通行区域，但不发送标注示意图。
- `obstacle_salience`：强调井道不可进入。
- `wording_shift`：改变信息顺序。
- `state_space`、`collision_check`、`image_text_consistency`：形式化分析角度变化。

## 5. 实验规模

如果使用 3 个模型、每条 Prompt 重复 2 次：

`12 prompts * 3 models * 2 repeats = 72` 条回复。

这足够作为单题跑通版本。后续如果老师要求更大规模，可以在同一 `T1` 场景上增加措辞扰动、尺寸微调和图文一致性扰动，而不是立即回到八个自定义场景。

## 6. 分析重点

本阶段重点回答：

- 多模态输入是否帮助模型理解真实楼梯转角结构。
- 模型是否严格遵守“井道不可通过”。
- 模型是否正确理解“只能直线移动，转弯需停车调向”。
- L1/L2/L3 表述变化是否导致判断翻转。
- 模型是否把照片中的管道、栏杆、墙面外观等非关键视觉信息误当成决定因素。

## 7. 标注关注点

除通用字段外，人工复核时重点检查：

- `final_judgment` 是否按模型最终结论标注。
- `failure_mode=obstacle_ignorance`：模型是否借用了右上井道或忽略不可通行区域。
- `failure_mode=unsupported_assumption`：模型是否从照片中擅自估计文字未给出的尺寸。
- `failure_mode=concept_confusion`：模型是否混淆轮椅宽度、长度、转向空间和直线分段路径。
- `spatial_modeling_depth` 是否区分了简单尺寸比较和真正的刚体/配置空间建模。
