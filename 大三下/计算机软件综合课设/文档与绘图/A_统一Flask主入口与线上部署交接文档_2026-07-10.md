## 2. 主入口职责

`unified_app.py` 是全组在线演示用的唯一 Flask app factory。它负责：

1. 创建一个 Flask 应用实例。
2. 读取统一数据库路径 `DATABASE_PATH`。
3. 初始化 A/B/C 三个模块的数据访问对象。
4. 对同一个 SQLite 数据库执行各模块 `schema.sql` 初始化。
5. 把 A 的身份、权限、参数、日志能力注入给 B/C。
6. 注册 A/B/C 的 HTTP 路由。
7. 提供统一 `/health`。

主入口不把身份、权限、资源可用性、信用资格等可信结论交给前端决定，所有判断都在服务器端完成。

## 5. A 注入给 B/C 的回调

| 回调 | 提供方 | 使用方 | 说明 |
|---|---|---|---|
| `CURRENT_ACTOR()` | A | B/C | 从 Flask session 恢复当前登录用户与当前角色 |
| `CAN_MANAGE_LAB(user_id, lab_id)` | A | B/C | 校验实验室管理员管辖范围，系统管理员默认全局可管理 |
| `GET_PARAMETER(key, default)` | A | B/C | 读取系统参数，如取消免责时限、签到窗口 |
| `AUDIT(...)` | A | C，后续 B/D 也可用 | 写入操作日志 |
| `STUDENT_IS_ELIGIBLE(user_id)` | A 临时适配 | B | D 未接入前，当前只检查当前学生身份和账号状态 |
| `RESOURCE_IS_BOOKABLE(...)` | C | B | 判断设备/实验室当前是否可预约 |

### 6.2 兼容旧调用

C 模块当前调用审计日志时仍使用旧参数名：

```python
target_type=...
target_id=...
```

A 的 `PlatformStore.audit()` 已兼容旧参数名和新版参数名：

```python
target_object_type=...
target_object_id=...
```

因此 C 模块不用立即改代码，后续有时间时可以逐步切到新版字段名。

### 6.3 越权审计

A 的管理接口权限拒绝、非法角色切换等越权行为会写入：

```text
action = auth.access_denied
```

这对应 FR-01 中“越权访问记录操作日志”的验收要求。
