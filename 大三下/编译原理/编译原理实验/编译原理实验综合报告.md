## 二、系统功能概述

本系统面向实验指导书中的简单教学语言，完成从源程序文件到中间代码的编译前端处理。系统定位不是完整的 C 编译器，而是一个“小型语言 -> Token 序列 -> 语法结构 -> 三地址代码”的教学型翻译系统。系统的主要功能如下：

- 从 `input.txt` 读取源程序，支持多行、多语句输入。
- 对源程序进行词法分析，输出 `tokens.txt`。
- 对 `Token` 序列进行语法分析，输出 `parse.txt` 和 `parse_tree.txt`。
- 在语法分析过程中同步进行语法制导翻译，输出 `tac.txt`。
- 记录词法、语法和简单语义错误，输出 `errors.txt`。
- 额外维护标识符表 `symbols.txt` 与常量表 `constants.txt`，便于展示扩展能力。

系统支持的基本语言结构包括：

- 标识符：字母开头，后接字母或数字；
- 关键字：`if`、`then`、`else`、`while`、`do`；
- 常量：十进制整数、八进制整数、十六进制整数；
- 扩展常量：十进制实数、八进制实数、十六进制实数；
- 运算符与分隔符：`+ - * / > < = ( ) ; { }`；
- 语句类型：赋值语句、`if-then`、`if-then-else`、`while-do`、复合语句块。

系统运行方式包括命令行模式和图形界面模式。命令行模式适合批量测试和自动输出文件；图形界面模式适合课程验收时现场展示输入、输出与错误处理过程。综合版系统的特点是接口统一、模块清晰、输出文件完整、便于扩展和演示。

## 三、系统总体结构

系统采用“词法分析 -> 语法分析 -> 语法制导翻译 -> 文件输出”的分层流水线结构，其总体流程如下：

```text
源程序 input.txt
    -> Lexer.scan() 逐个产生 Token
    -> Parser 递归下降分析 Token 序列
    -> CodeGenerator 生成三地址代码
    -> pipeline 统一写出 tokens / parse / parse_tree / tac / errors
```

综合版系统的核心模块划分如下：

- `src/token_defs.py`：统一定义 `TokenType`、`Token`、关键字表、运算符表以及输出名称。
- `src/lexer.py`：实现词法分析器 `Lexer`，对外只暴露 `scan()` 接口。
- `src/parser.py`：实现递归下降语法分析，并在分析过程中同步生成三地址代码。
- `src/codegen.py`：实现 `newtemp()`、`newlabel()`、`emit()` 等中间代码生成工具函数。
- `src/pipeline.py`：封装完整编译流程，负责调用各阶段并统一输出结果文件。
- `main.py`：命令行入口。
- `gui_tkinter.py` / `gui_pyqt6.py`：图形界面入口，便于课程验收演示。

在接口设计上，本系统坚持“上层不直接操作下层内部状态”的原则。语法分析器不能直接读取字符流，只能通过词法分析器的 `scan()` 获取下一个 `Token`；三地址代码生成器不参与具体语法判断，而是由语法分析过程在恰当的时刻调用 `emit()` 输出代码。这样的分层设计保证了系统结构清晰，也便于以后继续扩展语义分析、目标代码生成或优化模块。

## 四、词法分析子系统

### 4.1 正规式描述

词法分析器首先根据首字符把输入分配到标识符、数字、运算符、分隔符或错误处理分支。基础 `Token` 的正规式可以表示为：

```text
letter      -> [A-Za-z]
digit       -> [0-9]
octdigit    -> [0-7]
hexdigit    -> [0-9a-fA-F]

IDN         -> letter(letter|digit)*
INT10       -> 0 | [1-9][0-9]*
INT8        -> 0[0-7]+
INT16       -> 0[xX][0-9a-fA-F]+
REAL10      -> (0|[1-9][0-9]*)\.[0-9]+
REAL8       -> 0[0-7]+\.[0-7]+
REAL16      -> 0[xX][0-9a-fA-F]+\.[0-9a-fA-F]+
KEYWORD     -> if | then | else | while | do
OP          -> + | - | * | / | > | < | = | ( | ) | ; | { | }
```

其中，`IDN`、`INT10`、`INT8`、`INT16` 是实验指导书要求的基本识别对象；`REAL10`、`REAL8`、`REAL16` 属于综合版在原实验基础上的拓展能力。综合版还在基础标识符规则之上，允许识别 `my_var`、`obj.field` 这类更接近实际程序设计语言的变量形式，但实验基本要求仍以“字母开头，后接字母或数字”为主。

### 4.2 变换后的正规文法

根据上述正规式，可以得到右线性文法的主要形式如下：

```text
1. 标识符
I  -> letter A
A  -> letter A | digit A | ε

2. 十进制整数
N  -> 0 | nz B
B  -> digit B | ε

3. 八进制整数
O  -> 0 Q
Q  -> octdigit Q | octdigit

4. 十六进制整数
H  -> 0 x Y | 0 X Y
Y  -> hexdigit Y | hexdigit

5. 十进制实数
R10 -> N . D
D   -> digit D | digit

6. 八进制实数
R8  -> O . P
P   -> octdigit P | octdigit

7. 十六进制实数
R16 -> 0 x Y . Z | 0 X Y . Z
Z   -> hexdigit Z | hexdigit
```

关键字和运算符的识别本质上也可以看成特殊的有限自动机分支，但在实现时更适合通过保留字表和运算符表直接完成映射，因此没有单独展开为完整文法集合。

### 4.3 状态转换图说明

词法分析器的核心思想是确定有限自动机（DFA）。综合版虽然使用代码实现，而不是在程序中显式构造状态图，但其识别流程可以概括为以下几个主要状态：

- `S0`：初始状态。跳过空白字符；遇到字母转入标识符状态；遇到数字转入数值状态；遇到运算符或分隔符直接接受；遇到其他字符进入错误状态。
- `S1`：标识符状态。持续读取字母和数字；识别结束后查关键字表，若为保留字则返回关键字 `Token`，否则返回 `IDN`。
- `S2`：前导 `0` 状态。若后继为 `x/X`，转入十六进制状态；若后继仍为八进制数字，转入八进制状态；若后继为 `.`，转入实数状态；若后继为空白或分隔符，则把单独的 `0` 当作十进制整数处理。
- `S3`：十进制整数状态。持续读取十进制数字；若遇到 `.` 则转入十进制实数状态，否则接受为 `INT10`。
- `S4`：十六进制状态。读取 `0x/0X` 后持续读取十六进制数字；若遇到 `.` 则转入十六进制实数状态，否则接受为 `INT16`。
- `S5`：八进制状态。持续读取 `0-7`；若遇到 `.` 则转入八进制实数状态，否则接受为 `INT8`。
- `S6/S7/S8`：实数状态。继续读取小数部分，若小数部分为空或包含不合法字符，则生成错误 `Token`；否则接受为对应的实数类型。
- `SE`：错误状态。记录当前字符及其所在行列号，向 `errors.txt` 写入 `LexicalError` 信息。

根据上述状态和转移关系，可以直接绘制出实验要求中的状态转换图；综合报告中采用文字化说明，既保留了状态图的设计思路，也与最终程序实现保持一致。

### 4.4 主要数据结构与算法

词法分析子系统采用统一的 `Token` 数据结构：

```text
Token {
    type   : TokenType
    lexeme : 原始串
    attr   : 属性值
    line   : 行号
    column : 列号
}
```

其中，`lexeme` 保存源程序中的原始字面值，`attr` 保存经过语义归一化后的属性值。例如：

- `0x3f` 的 `lexeme` 为 `0x3f`，`attr` 为 `63`；
- `07` 的 `lexeme` 为 `07`，`attr` 为 `7`；
- `if`、`+`、`;` 等关键字和符号的 `attr` 统一记为 `_`。

`Lexer` 内部还维护以下辅助数据：

- `pos`、`line`、`column`：当前扫描位置与源程序坐标；
- `tokens`：已识别出的 `Token` 序列；
- `errors`：词法错误信息；
- `identifier_table`：标识符表，记录变量名、首次出现位置与出现次数；
- `constant_table`：常量表，记录常量类型、原始串、归一化值与出现次数。

`scan()` 的算法步骤如下：

1. 跳过空格、换行、制表符，同时更新行号和列号。
2. 若到达文件末尾，返回 `EOF`。
3. 若当前字符为字母，则进入标识符/关键字识别流程。
4. 若当前字符为数字，则按照“十六进制 -> 八进制/十进制 -> 实数”的顺序继续判断。
5. 若当前字符为运算符或分隔符，则直接返回对应 `Token`。
6. 若当前字符不属于任何合法类别，则生成 `TK_ERROR`，并写入错误信息。
7. 对已经识别出的标识符和常量更新表项，再把 `Token` 加入输出序列。

这种实现方式的优点是单次扫描即可完成识别、定位和归一化处理；语法分析器只需要重复调用 `scan()` 就可以按顺序获取输入单词，从而实现良好的模块解耦。

## 五、语法分析子系统

### 5.1 方法选择与改写后的产生式集合

单独实验阶段，我们曾使用 `Flex + Bison` 实现过一个 `LALR(1)` 语法分析器，用于验证文法设计和语法树构造的正确性；在最终综合版中，为了与手写词法分析器及实验三的属性翻译更自然地衔接，我们统一采用递归下降分析法，并对原文法进行了改写，消除了左递归，得到如下产生式集合：

```text
P  -> S ; P'
P' -> S ; P' | ε

S  -> id = E
S  -> if C then S
S  -> if C then S else S
S  -> while C do S
S  -> { P }

C  -> E > E
C  -> E < E
C  -> E = E

E  -> T E'
E' -> + T E' | - T E' | ε

T  -> F T'
T' -> * F T' | / F T' | ε

F  -> ( E )
F  -> id
F  -> int8 | int10 | int16
F  -> real8 | real10 | real16
```

该文法满足以下两个关键目标：

- 通过 `E/T/F` 三层结构自然保证乘除优先于加减；
- 通过把分号统一放在 `P -> S ; P'` 中处理，避免让每一种语句规则都重复处理语句结束符，结构更加清晰。

### 5.2 子系统结构

递归下降语法分析器中的主要函数与非终结符一一对应：

- `parseProgram()`：处理整个程序入口，对应 `P`。
- `parseStmt()`：处理赋值、条件、循环和复合语句，对应 `S`。
- `parseCond()`：处理关系表达式，对应 `C`。
- `parseExpr()`：处理加减表达式，对应 `E`。
- `parseTerm()`：处理乘除表达式，对应 `T`。
- `parseFactor()`：处理标识符、常量和括号表达式，对应 `F`。
- `match()`：匹配当前 `Token` 是否为预期类型。
- `synchronize()`：发生语法错误后跳到下一个 `;`、`}` 或 `EOF`，实现续编译。

系统输出两类语法分析结果：

- `parse.txt`：记录产生式及其在当前源程序中的真实含义，例如某个 `F -> int16` 对应的实际值可能是“10，源程序写作 0xa”。
- `parse_tree.txt`：使用缩进 ASCII 树展示语法层次结构，便于验收时直观展示 `while`、`if`、表达式嵌套等结构。

### 5.3 主要数据结构与算法

综合版语法分析器引入了两个关键辅助结构：

```text
TreeNode(label, children)
ExprResult(place, text, tree)
```

其中：

- `TreeNode` 用于构造 `parse_tree.txt` 所需的树形结构；
- `ExprResult.place` 表示当前表达式结果在三地址代码中的位置；
- `ExprResult.text` 表示当前表达式的人类可读文本；
- `ExprResult.tree` 用于把表达式部分也纳入语法树展示。

语法分析算法的核心思想如下：

1. 程序从 `parseProgram()` 进入，循环识别若干条 `S ;` 形式的语句。
2. `parseStmt()` 根据当前 `Token` 类型选择赋值、`if`、`while` 或复合语句分支。
3. `parseExpr()` 和 `parseTerm()` 使用循环而不是左递归函数调用来处理连续的加减、乘除运算，既避免左递归，也天然体现左结合性。
4. `parseFactor()` 处理最基本的语法单位：括号表达式、变量名和常量。
5. 每次识别到一条产生式时，系统把“产生式 + 当前真实含义”写入 `trace_rows`，最后统一格式化到 `parse.txt`。

例如，在识别 `while (a3+15)>0xa do ...` 时，`parse.txt` 中会输出如下信息：

```text
C -> E relop E             | C => (a3 + 15) > 10; 真->L1, 假->L2
F -> int16                 | F => 10，源程序写作 0xa
S -> while C do S          | S => while C do S; 每轮从 L0 判断，真进 L1，假跳 L2
```

这类“两栏输出”既保留了实验要求中的产生式推导轨迹，又补充了真实源程序语义，便于演示和答辩。

### 5.4 错误处理机制

语法分析子系统的错误处理遵循“定位明确、尽量续编”的原则。错误信息统一采用：

```text
SyntaxError at line 行号, column 列号: expected XXX, got YYY
```

当系统发现当前 `Token` 不满足预期时，不会立即崩溃退出，而是：

1. 记录行号、列号和预期/实际符号；
2. 跳过当前错误位置后的若干 `Token`；
3. 同步到下一个分号 `;`、右大括号 `}` 或文件末尾；
4. 尝试继续分析后续语句。

这种恢复策略虽然不能完成严格意义上的复杂错误修复，但足以满足课程实验“错误定位 + 后续续编译”的要求，也有利于展示系统的鲁棒性。

## 六、三地址代码生成子系统

### 6.1 语法制导定义

实验三的核心任务是在语法分析正确的基础上输出等价的三地址代码。综合版系统把三地址代码生成直接嵌入递归下降分析过程中，表达式使用综合属性，条件与控制语句使用继承式的标号信息。其核心语法制导规则可以概括如下：

```text
1. 赋值语句
S -> id = E
    emit(id := E.place)

2. 加法表达式
E -> E1 + T
    E.place = newtemp()
    emit(E.place := E1.place + T.place)

3. 乘法表达式
T -> T1 * F
    T.place = newtemp()
    emit(T.place := T1.place * F.place)

4. 条件表达式
C -> E1 relop E2
    emit(if E1.place relop E2.place goto C.true)
    emit(goto C.false)

5. if 语句
S -> if C then S1
    true_label  = newlabel()
    false_label = newlabel()
    C.true  = true_label
    C.false = false_label
    emit(true_label:)
    S1.code
    emit(false_label:)

6. if-else 语句
S -> if C then S1 else S2
    true_label  = newlabel()
    false_label = newlabel()
    end_label   = newlabel()
    C.true  = true_label
    C.false = false_label
    emit(true_label:)
    S1.code
    emit(goto end_label)
    emit(false_label:)
    S2.code
    emit(end_label:)

7. while 语句
S -> while C do S1
    begin_label = newlabel()
    true_label  = newlabel()
    false_label = newlabel()
    emit(begin_label:)
    C.true  = true_label
    C.false = false_label
    C.code
    emit(true_label:)
    S1.code
    emit(goto begin_label)
    emit(false_label:)
```

需要说明的是，综合版程序中并未把 `S.next` 显式保存为单独字段，而是通过 `begin_label`、`false_label`、`end_label` 等局部变量直接组织控制流；其本质上仍然对应属性文法中“语句后继位置”的设计思想。

### 6.2 主要数据结构

三地址代码生成器 `CodeGenerator` 的结构十分紧凑，主要包含：

```text
temp_count   : 当前临时变量编号
label_count  : 当前标号编号
lines        : 已生成的三地址代码序列
```

其核心接口为：

```text
newtemp()   -> t1, t2, t3, ...
newlabel()  -> L0, L1, L2, ...
emit(code)  -> 向代码序列追加一条三地址代码
```

综合版系统中，表达式相关属性主要通过 `ExprResult` 传递：

- `place`：当前表达式结果所在位置，可以是变量、常量或临时变量；
- `text`：当前表达式的可读形式；
- `tree`：用于语法树展示。

控制语句相关信息则通过分析函数中的局部标号变量传递，从而保证 `if`、`if-else`、`while` 的控制流正确。

### 6.3 算法基本思想

三地址代码生成的基本思想可以概括为“边分析、边翻译、边输出”：

1. 当语法分析器识别到一个因子 `F` 时，直接返回其 `place`。
2. 当识别到乘除或加减运算时，先递归求出左右操作数的 `place`，再申请新的临时变量保存结果。
3. 当识别到关系表达式时，直接生成“条件跳转 + 无条件跳转”两条控制流代码。
4. 当识别到 `if`、`if-else`、`while` 时，提前分配入口、真假出口和结束位置所需的标号。
5. 当发现类似 `c / 0` 的常量除零情况时，系统会记录 `SemanticError`，体现综合版对简单语义错误的检测能力。

这种设计的优点在于不需要先完整构建一棵大型中间树再统一翻译，而是把语法结构和代码生成自然结合起来，逻辑更紧凑，也更符合课程实验对“语法制导翻译”的要求。

## 七、典型输入输出示例

实验指导书中的经典测试输入如下：

```text
while (a3+15)>0xa do
if x2 = 07 then
while y<z do
y = x * y / z;
c=b*c+d;
```

词法分析输出 `tokens.txt` 的关键结果为：

```text
WHILE _
( _
IDN a3
+ _
INT10 15
) _
> _
INT16 10
DO _
IF _
IDN x2
= _
INT8 7
THEN _
```

从这一结果可以看出，十六进制常量 `0xa` 已被转换为属性值 `10`，八进制常量 `07` 已被转换为属性值 `7`，这为后续语法分析和代码生成提供了统一的数据表示。

语法分析输出 `parse.txt` 的典型片段如下：

```text
S -> while C do S          | S => while C do S; 每轮从 L0 判断，真进 L1，假跳 L2
C -> E relop E             | C => (a3 + 15) > 10; 真->L1, 假->L2
F -> int16                 | F => 10，源程序写作 0xa
S -> if C then S [else S]  | S => if C then S; 条件真->L3, 条件假->L4
F -> int8                  | F => 7，源程序写作 07
```

三地址代码输出 `tac.txt` 为：

```text
L0:
t1 := a3 + 15
if t1 > 10 goto L1
goto L2
L1:
if x2 = 7 goto L3
goto L4
L3:
L5:
if y < z goto L6
goto L7
L6:
t2 := x * y
t3 := t2 / z
y := t3
goto L5
L7:
L4:
goto L0
L2:
t4 := b * c
t5 := t4 + d
c := t5
```

上述结果与指导书参考代码在控制流意义上等价，说明系统已经能够正确处理：

- 常量属性归一化；
- 算术表达式优先级与左结合性；
- `while` 嵌套 `if` 再嵌套 `while` 的复杂控制流；
- 条件跳转、回边和出口标号的组织。

若输入中包含非法字符、缺少分号、括号不匹配或常量除零等情况，系统会把相应错误写入 `errors.txt`，从而体现出较完整的容错能力。

## 八、实验体会与思考

1. 词法分析不能仅靠空格分隔单词  
   源程序中经常出现 `c=b*c+d;`、`while(a<b)do...` 这类没有额外空格的写法。如果仅依赖空格切分，就无法正确识别运算符、分隔符和粘连在一起的标识符与常量。因此，词法分析必须基于字符级状态转移，而不能依赖人工排版。

2. 影响词法分析效率的关键在于状态设计和回溯控制  
   若扫描过程中频繁回退、重复判断，就会降低效率。实验中通过“首字符分流 + 有限状态连续读取”的方式，把大部分识别过程控制在单次线性扫描内，既提高了效率，也简化了实现。

3. 三地址代码虽然可以直接输出，但属性结构更适合复杂语法  
   对简单赋值语句而言，边分析边直接打印代码似乎已经足够；但一旦涉及嵌套表达式、条件跳转和循环回边，就必须借助 `place`、真假出口标号等属性信息统一组织中间结果，否则代码顺序很容易出错。

4. 运算符优先级和左结合性最好由文法层次保证  
   单纯依靠程序中的“先判断乘号再判断加号”容易产生遗漏，而把表达式拆成 `E / T / F` 三层后，乘除高于加减、同级左结合这些规则就自然体现在文法结构和分析流程中，程序逻辑更清晰，也更不容易出错。

5. 三地址代码中的标号可以看作相对地址的抽象形式  
   在当前实验阶段，我们使用 `L0`、`L1`、`L2` 这类符号标号表达控制流，已经足以描述程序语义。若继续向目标代码生成阶段扩展，只需在后续阶段把这些标号映射为具体地址或偏移量即可，因此现在的表示方式兼顾了清晰性和可扩展性。

6. 一个完整实验通常包括设计、实现和结果分析三个层面  
   本次实验不只是“把程序写出来”，还包括接口统一、测试样例设计、输出格式规范、错误处理、PPT 演示和综合报告撰写。通过这次实验，我们更清楚地体会到：真正的系统实现离不开前期设计、中期联调和后期分析总结，三者缺一不可。

本次综合实验把实验一的词法分析、实验二的语法分析和实验三的三地址代码生成成功整合到同一个编译前端系统中。系统实现了统一的 `Token` 接口、递归下降语法分析、语法制导翻译、错误定位与续编译、典型输入输出文件生成以及 GUI 演示能力。通过这次整合，我们不仅完成了各个单项实验的功能要求，也从系统工程角度体会到“模块接口统一、数据结构统一、错误处理统一”对于软件集成的重要性。
